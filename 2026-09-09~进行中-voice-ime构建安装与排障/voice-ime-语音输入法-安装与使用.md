# voice-ime 语音输入法：安装与使用

## 这是个什么

一个语音输入工具。在任何能打字的地方按住 Ctrl+Alt 说话，松开后文字直接落在光标处。

它不替换输入法，也不新增一个输入法。装上去之后，你原来用的搜狗（或任何一个拼音输入法）还是照旧，输入法列表里不会多出「语音」这一项，Ctrl+Space 轮到切换的还是原来那几个。它对系统只做一件事：给 fcitx 挂一个插件，在按键这一层监听按下与松开——说话时录音，松手时把文字交给当前窗口。

所以语音和拼音是同事关系，不是二选一：说完一句，接着用拼音敲字、改错字、翻候选，都还在同一个输入框里，不用切输入法，也不用调出任何面板。识别结果不进剪贴板。只上传按住那一段的音频，其余时间麦克风不工作。

## 先说我平时在用什么

我自己日常用的是[豆包输入法](https://shurufa.doubao.com/pc)。Windows、安卓、macOS 都有版本，唯独没有 Linux——如果你正好在这三个系统上，直接去下载用就好，不必折腾这个项目。

它的语音输入是我用过的里面最能打的，我自己对比下来比微信输入法还要再准一截；比起传统搜狗输入法，它没有任何广告和推荐弹窗，界面干净。这也是我愿意照着它，在 Linux 上补一个同类东西的原因。

## 为什么做这个

Linux 这条路是断的。日常办公的云桌面就是 NSDL 这类 Linux 系统，上面装不了豆包输入法，也没有别的等价替代品。等厂商支持不知道要等到什么时候，那就自己补上这一段。

而豆包输入法底下的语音能力来自火山引擎（豆包 SeedASR 流式语音识别），这套 API 对外是开放的。所以缺的其实不是识别引擎，只是把「按住说话」这一截接到 Linux 桌面输入框上——这个项目做的正是这一截。

## 为什么要多过一道大模型

传统语音输入是直的：说完一句，识别出什么就往光标处写什么。可说话和写字本来就不一样——「嗯」「那个」「就是说」这类口水词，说错了又自己改口的半句，说到一半重来的语序，直接落到文档里全是噪声，等于还得手动再删一遍。

豆包输入法也是这么处理的：先识别，再让大模型把这一句整理成书面语，然后才上屏。这个项目沿用同一思路，接的是通用的 OpenAI 兼容端点（DeepSeek 官方或内网 MaaS 网关）。

润色也不是自由发挥。提示词只允许删口头语、修语病、采纳自我纠正；英文、缩写、专有名词一律原样保留；不允许改写上一句，也不允许靠上文把半句补成整句。

## 有哪些特性

| 特性 | 说明 |
|---|---|
| 按住说话 | 长按组合键说话，松开停止并上屏，一句话一句 |
| 持续对话 | 触发后可松手继续说，按 Esc 结束并把整段上屏 |
| 拼音共存 | 不占输入法位，原有拼音输入法照常工作 |
| 浮窗提示 | 屏幕下方的声波条显示录音状态，颜色区分模式与润色进度 |
| 自动润色（可选） | 接一个大模型，把口头语、语病、自我纠正整理成书面语 |
| 热词 | 填一份专有名词表，识别时纠音、润色时纠写法，说 `Coclaw` 不再出 `call log` |
| 草稿窗 | 录一整段只进窗口不打扰光标，可复制、可优化后再用 |
| 快捷键自定义 | 两组组合键都能改，配置台里保存时校验 |
| 输入历史 | 识别原文与上屏文本逐句对照，可搜索 |

## 浮窗颜色

声波条只表示录音模式；润色状态改用卡片描边提示，两者不混用。

![[浮窗四色对照.png]]

实拍：润色中，声波条保持橙色，只有卡片描边转黄。声波随音量起伏——有声时拉高，静音时落回一条细线，一眼能看出麦克风有没有收到声音。

![[浮窗-润色中.png|520]]

| 外观 | 含义 |
|---|---|
| 青蓝声波 | 持续模式（A）：松手后继续录，按 Esc 结束并把整段上屏 |
| 橙色声波 | 即停模式（B，默认）：松开立即停止并上屏，一句话一句 |
| 橙条 + 黄描边 | 润色中：已松手，等大模型处理这一句，通常 1 至 2 秒 |
| 橙条 + 红描边 | 润色失败或超过 8 秒，红描边 1.5 秒后恢复 |
| 灰色细线 | 采集还没就绪（服务刚启动时短暂出现）：此刻开口会丢字，等它变彩再说话 |
| 红边卡片 + 红字「语音密钥无效 · 请在配置台「校验 Key」后保存」 | Key 被服务端拒绝（HTTP 401/403）。按下快捷键就出现，停留 4.5 秒，期间松不松手都不会被声波盖掉 |

模式用 Ctrl+Alt+Tab 切换，默认即停（B）。

红字提示还有一层提前量：同一个 Key 被拒过一次之后，**再按快捷键会当场提示**，不必等这轮握手跑完（握手通常 0.6 秒，但网络慢时会拖更久）。换了新 Key 或网络恢复后握手成功，提示自动消失，不需要重启服务。

## 安装

把下面的引导词整段交给 agent，它负责下载、检查依赖、安装、写密钥、验证。

需要准备两样，第二样可选：

- **火山引擎账号**：开通「流式语音识别」并为工具创建一个 API Key，步骤见下文「火山引擎语音识别」。新账号有免费额度，够日常用。
- **通用大模型（可选）**：只有用自动润色才需要，比如 DeepSeek 的 API Key。

### 引导词

```text
【任务】
在这台 Linux 机器上安装或更新 voice-ime 语音输入法：fcitx4 插件 + 豆包流式语音识别，说话即出字，不占用输入法位（拼音照常可用）。这一段步骤全新安装和升级通用——第 2 步先判断是哪种，其余步骤一样跑。安装包里的引擎已经编译好，不需要 gcc、make 或 fcitx-devel。请一步一步执行，每步做完报告结果；某一步失败就停下来说明现象，不要跳过、不要自己换方案。

【第 1 步：确认环境】
这是 Linux + fcitx4 桌面（X11 或 xrdp）。
    echo $XDG_SESSION_TYPE; command -v fcitx && fcitx-remote; python3 -V; /usr/bin/python3.6 -c "import gi" && echo gtk-ok
- 没有 fcitx（只有 fcitx5 或 ibus）：停止，说明本包只支持 fcitx4。
- fcitx-remote 返回 0/1：说明 fcitx 已装但未激活，属于正常，后面会重启。

【第 2 步：判断全新安装还是更新】
    cat ~/workspace/voice-ime/VERSION 2>/dev/null \
      || { [ -d ~/workspace/voice-ime ] && echo "旧版(无 VERSION 文件)" || echo "全新安装"; }
- 输出「全新安装」→ 第 5 步必须问用户要密钥。
- 输出「旧版(无 VERSION 文件)」或旧版本号（如 2026.10.29.11）→ 更新：第 5 步跳过，完成后告诉用户从哪个版本升到 2026.10.29.12。

【第 3 步：下载、校验、覆盖代码】
安装目录必须是 ~/workspace/voice-ime（引擎日志路径在编译时写死在这个位置，装到别处只是丢掉引擎日志，功能不受影响）。

    unzip -q -o /tmp/voice-ime.zip -d ~/workspace
    cd ~/workspace/voice-ime && chmod +x install.sh service.sh *.py && cat VERSION
安装包里不含 config.json 和 logs/，覆盖不会动到凭证和历史日志；上一行的备份只是兜底。

【第 4 步：依赖检查】
    cd ~/workspace/voice-ime && ./install.sh --check
只体检、不装任何东西，缺什么会列出来。内网 yum 必须显式带 no_proxy，否则走代理报 302：
    sudo -n env no_proxy=nsdlmirrors.zte.com.cn,.zte.com.cn yum install -y <缺的包>
- core 需要 python3.10 及以上，且能 import websockets；找不到时用 ~/.local/bin/python3（可用 pip install websockets）。

- 后面要 sudo install，需要 sudo 免密；sudo -n true 失败就先让用户执行一次 sudo -v。

【第 5 步：密钥（仅全新安装或 key 为空时才做）】
先看现状：
    cd ~/workspace/voice-ime
    if [ -f config.json ]; then
        python3 -c "import json;print('key 长度', len(json.load(open('config.json'))['doubao'].get('api_key','')))"
    else
        cp config.example.json config.json && echo "新配置已生成，需要填 KEY"
    fi
- 已有 config.json 且 key 长度大于 0：跳过本步，不要问用户要密钥。
- 没有 config.json 或 key 为空：向用户索要火山引擎语音识别 API Key（豆包语音控制台 → API Key 管理，形如一串 UUID），再执行：

    d = json.loads(p.read_text(encoding="utf-8"))

- 更新场景：ActiveEnterTimestamp 应是刚才的时间（服务确实重启过），日志里不应出现 Traceback。
- fcitx-remote 返回 1：按一次 Ctrl+Space 激活输入法，再验一次。
- 然后请用户在一个能打字的地方长按 Ctrl+Alt 说一句话，松手后文字应进入光标处。这一步只能由用户实做，你负责看日志。
```

## 使用

两组组合键对应两种录音方式。

| 操作 | 行为 |
|---|---|
| 按住说话组合，超过 0.3 秒 | 开始录音，出现声波浮窗；听到提示音说明采集已就绪 |
| 松开说话组合 | 停止录音，识别并提交到当前输入框 |
| 按住持续对话组合 | 触发后可松手继续说，按 Esc 结束并提交 |
| 录音中单按 Ctrl / 空闲时三键 | 切换草稿窗，内容不发往输入框 |
| 停顿约半秒 | 当前句子定稿，后续内容作为新的一句 |

两组组合的默认值与改法见下节。前提：fcitx 处于激活状态。

一直按着就一直录，不会因为中途停顿自动结束；只有松开组合键（持续模式下按 Esc）才停止上屏。

### 开头不会吞字

按下快捷键到真正开始采集之间有个看不见的空档：服务要拉起 parec 采集进程，而 xrdp 的音频源从进程启动到交出第一块音频要 1.1 秒左右（换采样率、调各种缓冲参数，实测都一样）。这段时间麦克风根本没在采——用户看到浮窗就开口，开头一两个字必然丢。

现在常驻一条采集流：服务启动时就把 parec 拉起来一直在采，音频只进一个三秒的内存队列；按下瞬间直接接管，队列里按键之前的部分当场清空，只送按住之后的。第一次按下也是毫秒级开始录。

两道确认：

- 浮窗未就绪时画灰线，第一块音频到手才转彩色声波。
- 提示音由「按下即响」改成「就绪才响」——听到那一声再开口，一个字都不会被吞。

想关掉常驻采集，在 `config.json` 里写 `"warm_mic": false`，就回到老行为：每次按下现拉进程，开头约 1.1 秒是空的，浮窗会先用灰线示警。

## 快捷键设置

两组组合都能在配置台修改：默认 Ctrl+Alt（按住说话）与 Ctrl+Alt+Space（按住持续对话），改完重启服务生效。

![[配置台快捷键卡片.png|680]]

**设置方式**：点一下输入框直接按想要的组合键，松开即填入，Esc 取消。修饰键支持 `ctrl`、`alt`、`shift`，末尾可带一个普通键（`space`、`tab`、单个字母数字）。

- 必须包含至少一个修饰键；裸键会和日常打字冲突，界面与服务端都会拒绝。
- 两组组合不能相同，保存时会校验。
- 持续组合可以以说话组合开头。按下末尾那个键时，从对讲机升级为持续模式。
- 组合含普通键时，该键在组合生效期间会被消费，不会输入到当前应用；组合未按满时照常透传。

## 长句续接

单次识别会话有 300 秒兜底上限（正常一次说话远到不了）。到点前静默换一次识别会话：录音流不中断、切换窗口的音频先缓存再补发，内容零丢失。

长句不会再被拆成多段上屏，也不会被分段润色。

## 自动润色

自动润色需要另配一个通用大模型（OpenAI 兼容端点，例如 DeepSeek）。不开也能正常用，输出就是识别原文。

打开配置台的「自动润色」后，每句定稿先送大模型处理，再提交上屏。行为约定：

- 候选栏先显示识别原句，润色返回后由结果替换，等待期间不空白。
- 请求携带最近 3 个已上屏的句子作为上下文，只用于理解指代，不允许改写上文。
- 前一句未完成时，新句子直接提交原文，保证顺序且延迟有上限。
- 失败或超过 8 秒，提交识别原文。

润色规则（提示词）可在配置台编辑。模型列表支持多个端点，下拉切换即持久化。默认关闭。

## 热词

专有名词是语音识别的天然弱点：内部系统名、英文术语、同事的名字，一开口就容易听成别的词——说 `Coclaw` 出来 `call log`，说 `influxdb` 出来 `Inflex CBN`。

配置台里有一份热词表，填进去的词会同时走两条链路：

- **识别阶段**：随每次识别请求发给豆包，在「读音接近、且原文本身说不通」时替换成你写的词。
- **润色阶段**：作为一张【专有名词表】附在润色提示词后面。判断只看读音：念 `Coclaw` 被听成 `call log` 这类才改回；原句说的本来就是别的词（哪怕跟这个项目沾边，比如「可口可乐」），一个字都不动。

两条链路都只认读音，不认语义。实测：说「帮我 check 一下 call log 的配置」，润色会认成 `Coclaw`；说「可口可乐这个项目怎么跑」，原样保留。早先版本这条规则写成了「相关就改」，把一句里的「逼贼狗」也套成了 `Coclaw`——现在宁可漏改，不能错改。

| 事项 | 说明 |
|---|---|
| 填什么 | 自己和常打交道的同事名、内部系统名（`context-hub`、`edw`、`zmail`）、英文术语（`influxdb`、`RDC`）、总被听错的谐音词。几十个足够，不必穷举 |
| 怎么写 | 按你希望上屏的样子写，大小写敏感：要 `CoClaw` 就写 `CoClaw` |
| 怎么加 | 配置台热词框里回车或逗号添加，也可整段粘贴；点 × 删除 |
| 何时生效 | 保存后下一句录音就生效，不用重启服务 |
| 代价 | 识别侧随首个请求带一次，润色侧只是几十字提示词，无可感延迟 |

边界：识别侧只在「音近且说不通」时才换词——说 `please check the coclaw repository`，模型认为 `call log history` 本身通顺，就不动，由润色兜底。润色侧同理：读音对不上，宁可不改。

想确认有没有生效，服务日志里逐句能看到三段：`热词 N 个: …`（词已带上）→ `识别结果: '…'`（识别侧）→ `润色 0.79s: '原文' -> '结果'`（润色侧）。

3. **创建 API Key**：左侧「API Key」→「创建 API Key」，名字随意（比如 voice-ime）；建好后点行尾的眼睛图标显示完整密钥，复制那一串 UUID。

## 额度与计费

免费额度按音频时长扣减，不按消息条数。按住说话 10 秒消耗 10 秒额度，静音段同样计入，因为服务端收到的是连续音频流。

- 新账号开通后有一段免费时长，当前活动为 20 小时；不同活动或档位可能为 10 小时，以控制台「资源额度」显示为准。
- 免费额度用完后转为后付费，单价以控制台计费页为准。
- 不希望产生费用，可在控制台暂停服务；此时语音识别不可用，其余功能不受影响。
- 停顿判停窗口调小，句子说完立即结束，长静音不会一直计费。

## 配置台

浏览器打开 `http://127.0.0.1:19530`。修改后点保存写回配置，写盘前自动备份。

| 区块 | 可修改内容 |
|---|---|
| 豆包 SeedASR | API Key、标点/数字书面化/语义顺滑/首字加速/二遍定稿/输出分段开关、停顿判停、起音保护、加速率；流式端点固定，不在界面暴露 |
| 快捷键 | 按住说话与按住持续对话两组组合，保存时校验格式与重复 |
| 采集与判停 | 只读展示录音设备、采样率、长按阈值、静音停止时间 |
| 热词 | 机器名、系统名、英文术语的纠正表 |
| LLM 润色 | 多模型列表、自动润色开关、提示词编辑 |

改 API Key 要先点「校验 Key」：它拿当前填的值真连一次豆包（只握手不发音频，约 1 秒），返回 401 就说明 Key 无效。**校验没通过点保存会被拒绝**，避免把打错的 Key 写进配置、后面每次录音都失败。页面加载时输入框回填的就是当前生效的 Key，视为已校验；一旦改动，状态会变成「已修改，保存前需要重新校验」。

### 识别参数说明

界面上这三个数字的参数下面都带同样一段说明，这里汇总便于查阅。

| 参数 | 含义 | 推荐值 |
|---|---|---|
| 停顿判停 ms | 句末静音持续到这里长就判定这句说完、立即定稿上屏。调小响应更快，但容易把一口气切成好几句；调大句子更完整，上屏更迟 | 500–800，默认 800 |
| 起音保护 ms | 开口后这段时间内不判停，防止开头的换气、停顿被误切成两句；只在开口后已有语音时起作用 | 1000；开头停顿较久可到 1500，短句多可降到 500 |
| 加速率 score | 「首字加速」的加速强度，0–10。未勾选首字加速时不生效（输入框置灰）。数值越大首字回来越快，识别精度可能略降 | 1–2，默认 0 |

### 输入历史

配置台顶部的「输入历史」标签页，把每句上屏都记下来：识别原文、润色后的上屏文本、耗时与状态。左边一列是模型听到的，右边一列是真正进入光标处的，两者对照就能看出润色动了哪些地方。
